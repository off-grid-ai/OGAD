Off Grid change map

Name the thing you want to change. The map shows every place it lives, the order to change them in, the check that proves each step done, and what you must not change at the same time.

Click a cell to see its files. Amber cells ship to users but have no proof there.

The whole map

Each row is one concept from @offgrid/features, plus two pieces of plumbing. Numbers are files that build it (proof excluded). "Places" is how many surfaces you touch to change it. Click a row to plan that change.

How it makes changes easier

Before you edit

See the whole ripple

"Change Scribe tone" lists the shared rule, three app ports, two Pro tiers, the extension, the website pages and the tests. Nothing is found late.

Needs

Change in one order

Owner, then engine, then logic, then view, then data and copy, then proof. Each step waits for the step before it to pass its check.

Gate

Every step has a check

The tests on that surface run, then the hand-test rows on device. A step with no check shows red, so you write the check first.

Excludes

Know what collides

Concepts that share files cannot change in parallel. Everything else can go to a separate session safely.

Keeps itself current

A commit hook updates the map

Each commit rescans the changed files. A new file joins its concept, and a new surface for a concept shows up in the next plan.

Gets cheaper

Fewer places, smaller ripple

When a concept moves its logic into one shared owner, "places" drops and every later change gets shorter.

How this was built: every git-tracked file in shared, desktop, desktop/pro, mobile, mobile/pro, browser-extension and website was placed in a layer by its folder, and in a concept by its path name. Hand-test rows come from the desktop and mobile RELEASE_TEST_CHECKLIST.csv. Path names miss some files and catch a few wrong ones. The next pass should add imports and symbol names, so the map follows the code as well as the folders.
