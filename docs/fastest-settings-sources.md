# Fastest settings: sources

Every default the "Use the fastest settings" plan sets, with the published fact it rests on.
Rule: published sources only, no local measurement. Where sources disagree, the most recent
benchmark on the closest hardware and engine version wins.

Engine versions this table is checked against (`resources/engine-pins.json`):

- llama.cpp `b11889` (2026-10-25)
- stable-diffusion.cpp `master-1015-e41fbcf`
- whisper.cpp `v1.9.5`

Where the values live:

- Chat plan: `planFastestSettings` and `SPEED_DEVICE_ROWS` in `shared/packages/models/src/fastest-settings.ts`, called by `src/shared/best-settings.ts`.
- Team mode slots and batch: `llmSlotPlan` and `teamBatchFlags` in `shared/packages/models/src/gateway-concurrency.ts`.
- llama-server argv: `buildLaunchArgs` in `src/main/llm/settings-math.ts`.
- Image: `src/main/imagegen/args.ts` and `src/main/sd-server.ts`. Speech: `src/main/transcription/whisper-server.ts`.

Audited 2026-10-27.

## Video

The fastest-settings plan does not set any video value. `videoEngineSettings` (shared) picks the
sampler, flow shift, and VAE-on-CPU for the Wan 2.2 VAE on Mac. These are correctness choices, not
speed defaults. Not changed.

## Follow-ups (not changed here)

- A published Metal `-ub` sweep for single-request chat on 16–32 GB Macs.
- MoE spill batch on Metal: no source either way.
- sd.cpp: replace the deprecated `--diffusion-fa` with `--flash-attn off,diffusion=on` (same behavior).
- Team mode with MTP on qwen4exp models ([#30368](https://github.com/ggml-org/llama.cpp/issues/30368)).
- MTP host-memory growth on long Metal sessions ([#30174](https://github.com/ggml-org/llama.cpp/issues/30174)): a memory issue, not a speed one.
- Phones: the KV cache and MTP-on rules differ from desktop without a published source. See Phones below.
